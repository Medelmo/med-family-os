# ADR-008 Internationalization: next-intl

Status: Accepted

## Decision
Use `next-intl` for German/English (initial) and French/Arabic-ready (future)
internationalization.

## Context
CLAUDE.md requires German and English from the start, no hardcoded
user-facing strings in components, and architecture-readiness for French and
Arabic/RTL. The scaffold named this requirement but pinned no library.

`next-intl` was chosen over `react-intl`/`i18next` because it is built for
the Next.js App Router specifically: it supports Server Components without a
client-side provider tax on every page, integrates with `next/navigation`
for locale-prefixed routing, and uses ICU MessageFormat (needed for correct
plural/number/date handling in German, which has different pluralization and
formatting rules than English).

## Consequences
- Add `next-intl` to `package.json` in Phase 1.
- All user-facing strings live in `messages/{locale}.json` (or feature-scoped
  equivalents), never inline in components.
- Dates, numbers, and currency use `next-intl`'s formatters (backed by
  `Intl`), not manual string formatting, satisfying CLAUDE.md's
  locale-aware-formatting requirement.
- RTL (Arabic) is deferred implementation but the message-key structure and
  routing are chosen now so it does not require a rewrite later — components
  must use logical CSS properties (`margin-inline-start`, not
  `margin-left`) once RTL is in scope.
